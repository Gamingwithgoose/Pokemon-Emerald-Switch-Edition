# Pokémon Emerald — Switch build pack

## What you need to supply

These files are **not included**. Add your own copies before building.

| File | Where it goes |
| --- | --- |
| Your `prod.keys` | `switch files/prod.keys` |
| Original LeafGreen ExeFS: `main`, `main.npdm`, `rtld`, `sdk`, `subsdk0` | `switch files/exefs/` |
| LeafGreen's `control.nacp`, from Control #0 | `switch files/control 0/control.nacp` |
| Vanilla English Pokémon Emerald, 16 MiB, as an uncompressed `.gba` | `Emerald rom/` |
| Optional home screen image: PNG, JPG, JPEG, WebP, or BMP | `Homescreen Icon/` |

Use the original **Switch Pokémon LeafGreen v0**, application ID
`010034D02340E000`. This builder checks the exact files used for the tested build:

- `main` Build ID: `a8dd9bcc29745ae5be9635a11a42dcbd90071181`
- `subsdk0` Build ID: `cd3cc7e5082efeca93bd5d39ff3c17b94d63ea50`
- Emerald ROM SHA-256: `a9dec84dfe7f62ab2220bafaef7479da0929d066ece16a6885f6226db19085af`

Keep the ExeFS filenames exactly as shown, without adding `.bin` or `.nso`.
You do not need a LeafGreen ROM, a RomFS dump, a save file, the old Emerald NSP,
or a separate RTC/save IPS patch. The build pack includes the patch data.
Only `control.nacp` is needed from Control #0; the original icon is optional
and isn't used automatically.

This guide starts with files you already have. It does not cover obtaining
keys, game dumps, or ROMs.

## 1. Install Python

Use **Python 3.14, 64-bit**, on a Windows 10 or Windows 11 x64 PC.
The builder was tested with Python **3.14.6**. See `Required Software.txt`
for the download link and exact package versions.

If the installer offers **Add Python to PATH**, select it. Keep pip and the
Python launcher enabled. Close and reopen PowerShell after installation.

The first build needs an internet connection to install the Python dependencies.
The script puts them in this pack's `.venv` folder.

## 2. Extract the pack and check the folders

Extract the whole ZIP to a writable folder. Don't run `build.bat` from inside
the ZIP. Keep `builder`, `tools`, and `source` alongside the build files.

If you cloned the GitHub repository or used GitHub's **Download ZIP**, Git
won't have preserved the empty input folders. Open PowerShell in the extracted
folder and run this once:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -PrepareFolders
```

The supplied build-pack ZIP already contains the empty folders.

## 3. Add your files

Arrange them like this. The Emerald ROM can have any filename ending in `.gba`,
but keep just one ROM in that folder.

```text
Emerald Build Pack/
  build.bat
  build.ps1
  switch files/
    prod.keys
    exefs/
      main
      main.npdm
      rtld
      sdk
      subsdk0
    control 0/
      control.nacp
  Emerald rom/
    Pokemon Emerald.gba
  Homescreen Icon/
  Release/
  builder/
  tools/
  source/
```

Copy the files into those folders directly. Avoid an extra nested `exefs`
folder or an extra `0` folder around `control.nacp`.

For a custom icon, put **one image** in `Homescreen Icon`. A square image works
best. The builder resizes it to 256 × 256 and converts it to JPEG. Leave the
folder empty to use the simple green emerald symbol generated by the builder.

## 4. Build

Double-click **`build.bat`**. It sets up Python packages, checks your inputs,
builds the application, and checks the finished NSP. The window stays open
so you can read the result.

Or open PowerShell in the build-pack folder and run:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

Both methods run the same builder. Neither needs administrator rights.
The execution-policy setting applies only to that PowerShell process.

When it says **Done**, your installer is here:

```text
Release/Pokemon_Emerald.nsp
```

`Release/build-record.json` records the build IDs and NSP hash.
`Release/verification.json` should say `PASS`.
Your input files stay unchanged. A later successful build replaces the NSP
in `Release`; a failed build leaves the previous one there, so check the final
message before copying an installer.

## 5. Install and test

1. Back up any existing standalone Emerald save with your save manager.
2. Copy `Release/Pokemon_Emerald.nsp` to your Switch and install it with the
   installer you normally use under Atmosphère.
3. Launch **Pokémon Emerald** from the HOME menu. A LeafGreen installation
   is not required on that Switch.
4. Save in game, close the application, reopen it, and check Continue.
5. Check that the clock advances after closing the game and after sleep.
6. For Emerald ↔ FireRed/LeafGreen trades, Emerald must have the National Dex
   and Champion progression. FireRed/LeafGreen must have unlocked Hoenn trading
   through Celio's Ruby/Sapphire quest. Otherwise the games can display
   “too far away” or “other trainers are not ready” even when discovery works.

The application displays **1.0.0 | Nintendo**, uses Title ID
`0100E04D454C0000`, and stores its ROM/save as `Emerald_e.gba` / `Emerald_e.sav`.
It has its own native save storage and can sit alongside LeafGreen. An existing
Emerald build using this same Title ID is the same application, so this installs
over it. Changing the icon does not create another save or Title ID.

This is a community modification. The displayed publisher field comes from
the requested metadata; it does not make this an official Nintendo release.

## If the build stops

- **Python not found:** install Python 3.14 x64, close the window, and try again.
- **Package installation failed:** check the connection. Corporate proxies and
  security software may block pip. Use the package versions in `Required Software.txt`.
- **Missing files:** use the exact paths printed in the error. Enable filename
  extensions in Explorer if a file may be named `prod.keys.txt`.
- **Unsupported dump or ROM:** the builder deliberately stops on other versions
  and modified ROMs. Check the supported files listed at the top. Seaglass and
  other ROM hacks are not supported by this pack.
- **Packaging or verification failed:** keep the failed run's `.build/run-.../build.log`.
  Review it before sharing; keep your keys and private inputs off GitHub.
- **Folders missing after cloning:** run the `-PrepareFolders` command in step 2.

The `.build` folder contains private intermediate game files. You can delete
it after building. Deleting `.venv` makes the next build install packages again.

To roll back, uninstall this Emerald application using your normal installer
or system software-management screen. It does not replace LeafGreen. Keep
your save backup if you want to restore it later.

If a console test fails, record whether it happened at launch, Continue,
saving, or wireless search. Export `Emerald_W3.bin` from the application's save
if present. For a crash, also collect the matching SD-card report from
`atmosphere/crash_reports` or `atmosphere/fatal_errors`, if one was created.

## What the pack changes

The builder patches the original Nintendo emulator rather than replacing it.
It adds cartridge RTC GPIO handling at `0x080000C4/C6/C8`, using the Switch system
clock, plus the verified Emerald save-completion gate. The W3 wireless bridge
connects eight Emerald RFU call sites to the emulator's existing native wireless
services while preserving the original RFU routines and callbacks.

The standalone metadata gives Emerald its own application/save identity while
retaining the original communication authorizations. The displayed version
stays 1.0.0; the internal content version is 8, matching the tested W3 build.

The previous build was tested on real Switch hardware for RTC, saving,
sleep/resume, Emerald ↔ Emerald communication, and Emerald ↔ FireRed trading.
This pack reproduces its executable build IDs and patched ROM hash. Every local
build also checks the embedded files, content hashes, metadata, and save owner
before copying the NSP into `Release`.

See `source/NOTES.md` for offsets, source details, credits, and limitations.
The repository includes scripts, patch data, and open-source tooling. Personal
keys, original executables, ROMs, saves, icons, and finished NSPs are excluded.
